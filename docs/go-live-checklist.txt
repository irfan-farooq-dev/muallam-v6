MUALLAM GO-LIVE CHECKLIST
=========================
Everything to do when deploying muallam.com, plus decisions and features left
for later. (Same content as docs/go-live-checklist.html.)


1. HOSTING (CPANEL)
-------------------
muallam.com is on cPanel shared hosting without a terminal: PHP 8.4 and
MariaDB 10.11 (seen in the old database export). Everything below is done
from cPanel, File Manager and phpMyAdmin. CPANELUSER = your cPanel username,
so the home folder is /home/CPANELUSER.

Layout: the app goes in /home/CPANELUSER/muallam (outside the web root, so
.env and the code can never be downloaded); only the public files go in
/home/CPANELUSER/public_html.

[ ] Select PHP Version (or MultiPHP Manager): PHP 8.4 for muallam.com, with
    extensions gd WITH WEBP SUPPORT (all image resizing uses it), pdo_mysql,
    mbstring, fileinfo, openssl, tokenizer, xml, ctype, bcmath; optionally
    exif (straightens sideways phone photos).
[ ] PHP options: upload_max_filesize >= 6M, post_max_size >= 10M.
[ ] MySQL Databases: create a new database (e.g. CPANELUSER_muallam) and a
    user with all privileges on it. Also add that user to the OLD database
    (so the old members can be copied), or put the old database's own login
    in LEGACY_DB_USERNAME / LEGACY_DB_PASSWORD. Keep the old database until
    the import has run.
[ ] SSL/TLS Status: certificate installed (AutoSSL). http:// and www. end on
    https://muallam.com (Domains > Force HTTPS Redirect).
[ ] Back up and clear the old site: download a copy of public_html and the
    old app folder, then empty public_html (keep .well-known and cgi-bin if
    present).


2. PRODUCTION .env
------------------
On your Mac, make the app key (never reuse the local one):

    php artisan key:generate --show

After the first upload (section 3) create /home/CPANELUSER/muallam/.env in
File Manager with:

    APP_NAME=Muallam
    APP_ENV=production          # also switches robots.txt to "welcome crawlers"
    APP_KEY=base64:...          # from key:generate --show
    APP_DEBUG=false             # never true on the live site
    APP_URL=https://muallam.com # used in emails, sitemap, share links
    APP_TIMEZONE=UTC            # see "Decisions still open"
    LOG_LEVEL=warning

    DB_CONNECTION=mysql
    DB_HOST=localhost
    DB_PORT=3306
    DB_DATABASE=CPANELUSER_muallam
    DB_USERNAME=CPANELUSER_...
    DB_PASSWORD=...

    # Old site's database: its members are copied on the first deploy.
    # Remove these lines afterwards.
    LEGACY_DB_DATABASE=CPANELUSER_...   # name of the OLD database
    # LEGACY_DB_USERNAME=...            # only if the user above has no access
    # LEGACY_DB_PASSWORD=...

    # public_html is not inside the app folder, so the image link needs the full path.
    PUBLIC_STORAGE_LINK=/home/CPANELUSER/public_html/storage

    SESSION_DRIVER=database
    SESSION_SECURE_COOKIE=true
    CACHE_STORE=file            # file, not database: the scheduler must work before the tables exist
    QUEUE_CONNECTION=database

    MAIL_MAILER=smtp
    MAIL_SCHEME=smtps
    MAIL_HOST=mail.muallam.com
    MAIL_PORT=465
    MAIL_USERNAME=no-reply@muallam.com
    MAIL_PASSWORD=...
    MAIL_FROM_ADDRESS="no-reply@muallam.com"
    MAIL_FROM_NAME="Muallam"

[ ] .env created with a new APP_KEY. Keep a safe copy of the whole file
    outside the server: if the key is lost, sessions and remember-me cookies
    stop working.
[ ] APP_DEBUG=false, APP_ENV=production and CACHE_STORE=file double-checked.
[ ] Changing .env later: settings are cached, so they only apply after a
    deploy. Without a new upload, edit muallam/RELEASE in File Manager (add
    "-1" to the end of the line); the scheduler redeploys within a minute.


3. UPLOAD AND DEPLOY
--------------------
Build the upload zip on your Mac from committed code (it includes the
Composer packages, so the server needs no Composer or terminal):

    php artisan site:package

It creates muallam-deploy/muallam-<commit>-<time>.zip next to the project,
holding two folders: muallam/ (the app) and public_html/ (the public files,
already pointed at ../muallam). Uncommitted changes are not included.

[ ] File Manager: upload the zip to /home/CPANELUSER (the home folder, not
    inside public_html) and Extract it there. Then delete the zip.
[ ] First time only: create muallam/.env (section 2) and add the cron job
    (section 4).
[ ] Within a minute the scheduler runs site:deploy: database tables,
    categories, old members (while LEGACY_DB_DATABASE is set), the
    public_html/storage image link and the caches. Read the result in
    muallam/storage/logs/deploy.log; it must end with "Release ... deployed."
    A failed step is retried every minute until fixed.
[ ] After the first deploy: check the log lists the imported members, then
    remove the LEGACY_DB_... lines from .env.
[ ] Later updates: commit, run php artisan site:package, upload and extract
    the new zip over the old folders (Overwrite). The new RELEASE file makes
    the scheduler deploy it. Keep the previous zip: extracting it again rolls
    back the code (database changes are not undone).

!! NEVER run plain "php artisan db:seed" or "migrate:fresh --seed" on the live
!! site. The default seeder creates demo users (password "password") and fake
!! posts. site:deploy only runs the safe CategorySeeder, which never deletes
!! anything.


4. SCHEDULER (CRON)
-------------------
cPanel > Cron Jobs > Add New Cron Job, "Once Per Minute" (* * * * *), command:

    cd /home/CPANELUSER/muallam && /opt/alt/php84/usr/bin/php artisan schedule:run >> /dev/null 2>&1

It finishes deploys (every minute, only when a new release was uploaded) and
runs posts:prune-images daily at midnight (deletes editor uploads never saved
into a post). The PHP path depends on the host: /opt/alt/php84/usr/bin/php on
CloudLinux (this host's MariaDB says "cll-lve", so likely), otherwise
/usr/local/bin/ea-php84 or /usr/local/bin/php.

[ ] Cron job added with your username and the right PHP path.
[ ] It works: muallam/storage/logs/deploy.log appears within a minute or two.
    If not, temporarily replace ">> /dev/null 2>&1" with
    ">> /home/CPANELUSER/cron.log 2>&1" to see the error (usually a wrong PHP
    path or a PHP older than 8.3), and put it back afterwards.


5. MEMBERS AND THE FIRST ADMIN
------------------------------
The first deploy copies the old site's members. They keep their passwords
(old addresses such as /abu-hashim/blogs redirect to the new author pages).
Skipped on purpose: one scam account and five bot sign-ups with random-letter
names. No old email address was ever verified, so members confirm theirs from
the dashboard before they can write.

The old admin@muallam.com ("Admin User") becomes an admin with the address
/users/admin-user.

[ ] Sign in as admin@muallam.com with its old password (or use "Forgot
    password" once email works), and open https://muallam.com/admin
[ ] Make your own account an admin from Admin > Users. (No admin can sign
    in? phpMyAdmin > SQL:
    UPDATE users SET role = 'admin' WHERE email = 'you@example.com';)


6. EMAIL DELIVERY
-----------------
The site sends: email verification, password reset, restricted-post invites.

[ ] cPanel > Email Accounts: create no-reply@muallam.com and use its
    password in MAIL_PASSWORD. Connect Devices shows the SMTP host and port
    (usually mail.muallam.com, 465 SSL).
[ ] cPanel > Email Deliverability: SPF and DKIM valid (Repair if not). Add a
    DMARC record too, so emails do not land in spam.
[ ] Send yourself one of each: sign up (verification), "Forgot password"
    (reset), invite yourself to a restricted post from another account
    (invite). Check links open https://muallam.com/...


7. SMOKE TEST AFTER GOING LIVE
------------------------------
[ ] Home, a category, a post, search and an author page load over HTTPS.
[ ] Sign up, verify email, sign in, sign out, reset password.
[ ] Profile: upload a photo (checks gd, WebP and storage:link), change slug,
    view the public bio page.
[ ] Write a post with a featured image and an image inside the text;
    Preview; Publish; open it signed out.
[ ] Like and comment from a second account; hide a comment as the author.
[ ] Restricted post: invite an address you can read, open the link signed
    out, enter the password, then revoke.
[ ] An unknown address shows the styled 404 page, not a Laravel debug page
    (proves APP_DEBUG=false).


8. SEO AFTER GOING LIVE
-----------------------
[ ] Open https://muallam.com/robots.txt: it must list the Disallow: rules and
    the Sitemap: line. If it says only "Disallow: /", APP_ENV is not
    production.
[ ] Open https://muallam.com/sitemap.xml: it lists public pages with https://
    addresses. (It refreshes at most once an hour.)
[ ] Google Search Console: add and verify muallam.com, then submit
    https://muallam.com/sitemap.xml
[ ] Bing Webmaster Tools: add the site (can import from Search Console) and
    submit the sitemap.
[ ] Test link previews: paste a post link into the Facebook Sharing Debugger
    and the LinkedIn Post Inspector; then share it on WhatsApp.
[ ] Test a post with Google's Rich Results Test (article data, breadcrumbs).
[ ] Optional: replace public/img/og-default.png (share image for posts
    without a featured image) with a designed 1200x630 image with your logo.


9. BACKUPS AND HOUSEKEEPING
---------------------------
[ ] Daily database backup (users, posts, comments, likes, invites):
    cPanel > Backup, or JetBackup if the host offers it.
[ ] Daily backup of muallam/storage/app/public/ - all uploaded avatars, featured
    images and post images live there. The database alone is not enough.
[ ] Keep .env (with APP_KEY) in a safe place outside the server.
[ ] Watch muallam/storage/logs/laravel.log for errors in the first days.
[ ] Optional tidy-up: delete AGENTS.md if you do not use other AI tools; trim
    unused Bootstrap/template files in public/frontend and public/admin to
    make the upload smaller. Once the import has run, the old database can be
    deleted (keep a downloaded copy).


10. DECISIONS STILL OPEN
------------------------
- Time zone: today APP_TIMEZONE=UTC, so scheduled posts and dates use UTC.
  Option: APP_TIMEZONE=Asia/Karachi so 10:00 means 10:00 local time.
  Decide BEFORE writers schedule posts.
- Hiding a comment that has replies: replies disappear with it but still
  count in the comment total. Option: make hidden threads uncount replies.
- Like button on post cards: cards show the count only (liking happens on
  the post page). Option: add a button to cards.
- GIF images: rejected (converter keeps only the first frame).
  Option: store GIFs as-is instead of converting.
