1. Hosting (cPanel)

muallam.com is on cPanel shared hosting without a terminal: PHP 8.4 and MariaDB 10.11 (seen in the old database export). Everything below is done from cPanel, File Manager and phpMyAdmin. Throughout, CPANELUSER stands for your cPanel username, so the home folder is /home/CPANELUSER.

Layout on the server: the app goes in /home/CPANELUSER/muallam (outside the web root, so .env and the code can never be downloaded) and only the public files go in /home/CPANELUSER/public_html.

2. Production .env

On your Mac, make the app key (never reuse the local one): php artisan key:generate --show. Then after the first upload (section 3) create /home/CPANELUSER/muallam/.env in File Manager with:

APP_NAME=Muallam
APP_ENV=production          # also switches robots.txt to "welcome crawlers"
APP_KEY=base64:...          # from key:generate --show
APP_DEBUG=false             # never true on the live site
APP_URL=https://muallam.com # used in emails, sitemap, share links
APP_TIMEZONE=UTC            # see "Decisions still open"
LOG_LEVEL=warning

DB_CONNECTION=mysql
DB_HOST=localhost
DB_PORT=3306
DB_DATABASE=CPANELUSER_muallam
DB_USERNAME=CPANELUSER_...
DB_PASSWORD=...

# Old site's database: its members are copied on the first deploy. Remove these lines afterwards.
LEGACY_DB_DATABASE=CPANELUSER_...   # name of the OLD database
# LEGACY_DB_USERNAME=...            # only if the user above has no access to it
# LEGACY_DB_PASSWORD=...

# public_html is not inside the app folder, so the image link needs the full path.
PUBLIC_STORAGE_LINK=/home/CPANELUSER/public_html/storage

SESSION_DRIVER=database
SESSION_SECURE_COOKIE=true
CACHE_STORE=file            # file, not database: the scheduler must work before the tables exist
QUEUE_CONNECTION=database

MAIL_MAILER=smtp
MAIL_SCHEME=smtps
MAIL_HOST=mail.muallam.com
MAIL_PORT=465
MAIL_USERNAME=no-reply@muallam.com
MAIL_PASSWORD=...
MAIL_FROM_ADDRESS="no-reply@muallam.com"
MAIL_FROM_NAME="Muallam"

3. Upload and deploy

Build the upload zip on your Mac from committed code (it includes the Composer packages, so the server needs no Composer or terminal):

php artisan site:package

It creates muallam-deploy/muallam-<commit>-<time>.zip next to the project, holding two folders: muallam/ (the app) and public_html/ (the public files, already pointed at ../muallam). Uncommitted changes are not included.

Never run plain php artisan db:seed or migrate:fresh --seed on the live site. The default seeder creates demo users (password password) and fake posts, and the live package does not even include the tools it needs. site:deploy only runs the safe CategorySeeder, which never deletes anything.

4. Scheduler (cron)

cPanel › Cron Jobs › Add New Cron Job, Once Per Minute (* * * * *), command:

cd /home/CPANELUSER/muallam && /opt/alt/php84/usr/bin/php artisan schedule:run >> /dev/null 2>&1

It finishes deploys (every minute, only when a new release was uploaded) and runs posts:prune-images daily at midnight (deletes editor uploads never saved into a post). The PHP path depends on the host: /opt/alt/php84/usr/bin/php on CloudLinux (this host's MariaDB says cll-lve, so likely), otherwise /usr/local/bin/ea-php84 or /usr/local/bin/php.

5. Members and the first admin

The first deploy copies the old site's members. They keep their passwords (old addresses such as /abu-hashim/blogs redirect to the new author pages). Skipped on purpose: one scam account and five bot sign-ups with random-letter names. No old email address was ever verified, so members confirm theirs from the dashboard before they can write.

The old admin@muallam.com ("Admin User") becomes an admin with the address /users/admin-user.

6. Email delivery

The site sends: email verification, password reset, and restricted-post invites.
