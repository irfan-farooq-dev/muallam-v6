2. Production .env

Copy .env.example to .env on the server and set at least:

APP_NAME=Muallam
APP_ENV=production          # also switches robots.txt to "welcome crawlers"
APP_DEBUG=false             # never true on the live site
APP_URL=https://muallam.com # used in emails, sitemap, share links
APP_TIMEZONE=UTC            # see "Decisions still open"

DB_CONNECTION=mysql
DB_HOST=...
DB_PORT=3306
DB_DATABASE=...
DB_USERNAME=...
DB_PASSWORD=...

SESSION_DRIVER=database
SESSION_SECURE_COOKIE=true
CACHE_STORE=database
QUEUE_CONNECTION=database

MAIL_MAILER=smtp
MAIL_HOST=...
MAIL_PORT=587
MAIL_USERNAME=...
MAIL_PASSWORD=...
MAIL_FROM_ADDRESS="no-reply@muallam.com"
MAIL_FROM_NAME="Muallam"

3. Deployment commands

Run from the project folder on the server, in this order:

composer install --no-dev --optimize-autoloader
php artisan key:generate              # first deploy only
php artisan migrate --force
php artisan db:seed --class=CategorySeeder --force
php artisan storage:link              # makes uploaded images reachable
php artisan optimize                  # caches config, routes, views, events
Never run plain php artisan db:seed or migrate:fresh --seed on the live site. The default seeder creates demo users (password password) and fake posts. Only CategorySeeder is safe; it can be run again any time and never deletes anything.

4. Scheduler (cron)

One cron line runs Laravel's scheduler every minute. Today it runs posts:prune-images daily at midnight (deletes editor uploads never saved into a post, older than 24 hours).

* * * * * cd /path/to/muallam && php artisan schedule:run >> /dev/null 2>&1

5. First admin account

There is no admin sign-up screen yet (the admin panel is a later feature). Register normally on the live site, verify the email, then promote yourself:

php artisan tinker --execute 'App\Models\User::where("email", "you@example.com")->update(["role" => "admin"]);'
